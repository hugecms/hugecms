## 1. 产品概述

### 1.1 产品定位

HugeCMS 是一套面向中小内容团队的**自部署内容管理系统**，提供从内容创作、审核、发布到运营分析的一站式能力，并通过响应式前台主题将内容呈现给终端读者。

### 1.2 背景与问题

中小内容团队（企业市场部、垂直媒体、独立创作者团队）在选择 CMS 时普遍面临三类矛盾：

1. **开箱即用 vs 可控性**：SaaS 建站平台上手快，但数据不在自己手里、定制受限、长期成本高；
2. **开源免费 vs 上手门槛**：传统开源 CMS（WordPress 等）生态成熟，但历史包袱重、安全隐患多、PHP 版本老旧，与现代技术栈脱节；
3. **功能全面 vs 维护成本**：大型商业 CMS 功能齐全，但授权昂贵、部署复杂，需要专职运维。

HugeCMS 的切入点：**现代技术栈（PHP 8.4 / Laravel 13）+ 云原生部署 + 覆盖核心场景的精简功能集**，让 3 人以内的小团队也能低成本拥有安全、可控、好用的内容平台。

### 1.3 产品目标

| 类型 | 目标 | 衡量方式 |
| --- | --- | --- |
| 业务目标 | 6 个月内完成 V1.0 上线，支撑至少 3 个种子团队日常使用 | 种子团队数、周活跃后台用户 |
| 业务目标 | 内容生产效率优于团队原有方案 | 单篇内容从创建到发布的平均时长下降 ≥ 30% |
| 用户目标 | 编辑 5 分钟内完成「注册登录 → 发文 → 发布」全流程 | 新手任务完成率 ≥ 80% |
| 用户目标 | 读者侧首屏加载时间 < 1.5s（常规网络） | 前台性能监控 P75 |
| 技术目标 | 可在 Google App Engine 标准环境一键部署（见 [部署指南](../deployments/appengine-standard.md)） | 部署成功率、部署耗时 |

### 1.4 价值主张

- **对编辑**：清爽的后台 + Markdown/富文本双模式编辑器 + 草稿自动保存，专注创作不被工具打扰；
- **对管理员**：精细的角色权限 + 完整的操作审计，多人协作不失控；
- **对开发者**：Laravel 13 标准代码结构 + 主题模板机制 + 开放 API，二次开发友好；
- **对老板**：数据自持、部署成本低（Serverless 按量计费）、无授权费用。

## 2. 目标用户与角色

### 2.1 用户画像

| 画像 | 描述 | 核心诉求 | 使用频率 |

### 2.2 角色与权限矩阵

权限模型采用 RBAC（基于角色的访问控制）。

| 功能域 | 超级管理员 | 管理员 | 编辑 | 作者 | 审核员 | 未登录用户 |
| --- | --- | --- | --- | --- | --- | --- |
| 内容发布 | ✅ | ✅ | ✅ | 仅自己的稿件（需审核） | ❌ | ❌ |
| 内容审核 | ✅ | ✅ | ❌ | ❌ | ✅ | ❌ |
| 全部内容管理 | ✅ | ✅ | 仅自己创建的 | 仅自己创建的 | 可读 | ❌ |
| 媒体库 | ✅ | ✅ | ✅ | 仅自己上传的 | 只读 | ❌ |
| 用户管理 | ✅ | ✅（不可管理超级管理员） | ❌ | ❌ | ❌ | ❌ |
| 系统设置 / 主题 | ✅ | 只读 | ❌ | ❌ | ❌ | ❌ |
| 操作日志查看 | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| 前台阅读 / 评论 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅（评论需登录或审核） |

> 说明：✅ = 有权限，❌ = 无权限。V1.0 内置以上 5 个角色 + 访客；自定义角色与细粒度权限点在 V1.2 提供。

## 3. 核心用户故事

**内容创作（编辑/作者）**

- US-01 作为编辑，我可以用 Markdown 或富文本写作，并实时预览效果，以便用顺手的方式产出内容；
- US-02 作为编辑，浏览器崩溃或误关后，我的草稿不丢失（自动保存），以便安心写作；
- US-03 作为编辑，我可以设置定时发布，以便在流量高峰时段自动上线内容；
- US-04 作为作者，我投稿后能看到审核状态与驳回原因，以便快速修改重投。

**内容运营（编辑/管理员）**

- US-05 作为编辑，我可以置顶、推荐、调整发布时间，以便控制内容在站内的曝光；
- US-06 作为编辑，误删的内容可以从回收站恢复，以便挽回损失；
- US-07 作为编辑，我可以查看每篇内容的阅读量趋势，以便判断选题质量。

**站点管理（管理员）**

- US-08 作为管理员，我可以为不同成员分配不同角色，以便安全地协作；
- US-09 作为管理员，我可以通过操作日志追溯任何一次内容变更，以便定责与审计；
- US-10 作为管理员，我可以配置站点 SEO 基础项（TDK、sitemap、robots），以便提升自然搜索流量。

**读者（前台）**

- US-11 作为读者，我可以按分类/标签浏览和关键词搜索内容，以便快速找到感兴趣的文章；
- US-12 作为读者，我可以对文章评论并收到回复，以便与作者互动。

## 5. 非功能需求

| 类别 | 需求 | 目标/说明 |
| --- | --- | --- |
| 性能 | 后台页面响应 | P95 < 800ms（常规操作） |
| 性能 | 前台页面响应 | P75 首屏 < 1.5s；列表/详情走页面缓存 |
| 性能 | 并发能力 | 单实例（App Engine F2）支撑 ≥ 50 RPS 只读流量（缓存命中场景） |
| 性能 | 数据规模 | 支持 10 万级文章、百万级评论下核心页面可用 |
| 安全 | 认证与会话 | HTTPS 强制；会话安全 Cookie；登录限流 |
| 安全 | 注入与攻击防护 | 框架层防 SQL 注入/XSS/CSRF；上传文件白名单与真实 MIME 校验 |
| 安全 | 权限最小化 | 所有后台路由经中间件鉴权，越权访问 403 并记日志 |
| 安全 | 依赖安全 | composer/npm 依赖无已知高危漏洞（CI 定期扫描） |
| 可用性 | 浏览器兼容 | Chrome/Edge/Firefox/Safari 最近两个大版本 |
| 可用性 | 移动端适配 | 后台关键页面（内容列表/编辑/审核）可用手机操作；前台全响应式 |
| 可用性 | 无障碍 | 前台核心页面满足 WCAG 2.1 AA 基础项（语义化标签、对比度、键盘可达） |
| 可维护性 | 代码规范 | 遵循 Laravel 最佳实践与仓库 CLAUDE.md 约定；Pest 测试覆盖核心流程 |
| 可维护性 | 日志与排障 | 结构化日志（stderr → 云日志）；错误分级告警 |
| 可扩展性 | 架构扩展 | 主题、插件机制预留；队列任务与事件驱动便于横向扩展 |

## 6. 技术约束与依赖

> 本章为研发约束参考，详细架构设计另见技术方案文档（待产出）。

1. **技术栈**：PHP 8.4 + Laravel 13 + MySQL 8.4；前端 Vite + Tailwind CSS 4；
2. **部署环境**：Google App Engine 标准环境（PHP 运行时只读文件系统）：
   - 上传文件必须使用对象存储（Google Cloud Storage，需新增 Flysystem GCS 适配依赖）；
   - session/cache/queue 使用 database 驱动（现状已满足）；
   - 定时发布、回收站清理等依赖队列与调度（见 [部署指南](../deployments/appengine-standard.md) 第 9 节）；
3. **编辑器**：富文本/Markdown 编辑器选型需在技术评审中确定（候选：Tiptap、Lexical、Editor.md）；
4. **依赖变更**：所有新增 composer/npm 依赖须经团队评审（仓库 CLAUDE.md 约定）。

## 7. 版本规划（Roadmap）

### V1.0 — MVP（目标：功能冻结后 8 周内上线）

**范围**：让一个 3 人团队开站运营的最小闭环。

- 账号与权限：邀请制建号、5 个内置角色（FR-501/502/504/505）
- 内容：文章 + 单页 + 分类 + 标签 + 回收站（FR-201~205、206、208、221、231、232）
- 编辑器：Markdown/富文本双模式 + 草稿自动保存 + 图片上传（FR-202/203）
- 媒体库：上传、GCS 云存储、基础管理（FR-401/402/404/405）
- 前台：默认响应式主题，首页/列表/详情/单页（FR-901）
- SEO：TDK、sitemap、robots、自动生成规则（FR-701/702/703）
- 系统维护：缓存管理（FR-1301）
- 仪表盘：数据卡片 + 最近动态 + 快捷入口（FR-101/102/103）

**MVP 明确不做**（防止范围蔓延）：评论、审核流、多语言、插件、开放 API、主题市场、第三方统计对接。

### V1.1 — 协作与运营增强（MVP 后 4–6 周）

- 审核工作流 + 通知（FR-301~303）
- 评论与敏感词（FR-601~603）
- 版本修订、批量操作、菜单管理、301 重定向、结构化数据（FR-207/209/222/704/705）
- 图片缩略图规格（FR-403）、站内搜索（FR-801）
- 数据统计看板（FR-104/1101/1102）、双因素认证（FR-503）
- 后台界面多语言（FR-1002）、数据备份（FR-1302/1303）

### V1.2 — 生态与扩展

- 自定义角色与细粒度权限
- 内容多语言（FR-1001）
- 主题机制开放（子主题/模板覆盖 FR-903）、主题切换（FR-904）
- 开放 API 与 Webhook（FR-1201/1202）
- 插件机制（技术预研后另立 PRD）

## 11. 术语表

| 术语 | 说明 |
| --- | --- |
| TDK | Title / Description / Keywords，搜索引擎结果中展示的页面元信息 |
| RBAC | Role-Based Access Control，基于角色的访问控制 |
| slug | URL 中可读的路径标识，如 `/posts/hello-world` 的 `hello-world` |

| JSON-LD | 结构化数据格式，辅助搜索引擎理解页面内容 |
| TOTP | Time-based One-Time Password，基于时间的一次性密码（双因素认证） |
| Webhook | 内容事件发生时向外部系统推送的 HTTP 回调 |
